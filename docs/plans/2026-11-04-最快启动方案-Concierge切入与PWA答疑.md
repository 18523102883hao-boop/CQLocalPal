## 四、PWA 答疑（潘总建议的技术评估）

**是什么**：Progressive Web App——用 Web 技术（Service Worker + Web App Manifest）让网站获得"类 App"能力：可安装到手机主屏、独立窗口运行、离线缓存内容。本质仍是网站，不是应用商店里的原生 App，**用户零安装成本**。

**能和现在的网站一起做吗**：完全可以，二者不是替代关系。PWA 是给网站"加一层 App 化能力"：我们的 Astro 静态站是 PWA 的最佳载体（静态资源最适合缓存），加 PWA ≈ 加一个 manifest 文件 + 一个 service worker 脚本，**约半天工作量**。

**手机端体验更好吗**：对，尤其适合我们的场景——欧美游客 iPhone 占比高：iOS 16.4+ 支持安装到主屏（用户需手动"添加到主屏幕"），推送通知支持仍有限制；Android 上体验完整。注意：PWA 不能替代 WhatsApp 聊天和在线支付（必须联网），**它的核心价值对我们是"离线可读"**。

**离线使用——恰恰是我们场景的最痛点**：客人落地机场那一刻往往没网！PWA 离线缓存能让客人**无网时打开确认单、落地指引 PDF、集合点照片**——这比"装一个 App"现实得多（没人愿意为中国旅行专门装 App，Jay/Anjia 都没做 PWA，这是小差异化）。

**谁在用/最佳实践**：Twitter Lite 与 Pinterest（PWA 后互动率显著提升，早期标杆）、Starbucks 点单、Uber 轻量版（m.uber.com）、Tinder、Spotify Web、AliExpress（移动端转化提升约 100% 的官方案例）。共性场景：网络不稳定地区、用户不愿装 App、内容/工具型产品——**三条全中我们的客群**。

**我的建议（排序）**：赞同潘总方向，但 PWA 是**加分项不是前置依赖**——① 单页接单版不装 PWA（够轻）；② 官网 v1 上线时带上 PWA，只开两个能力：安装到主屏 + 离线可读确认单/落地指引；③ 推送通知不开（iOS 限制+维护成本，WhatsApp 已承担触达）。
