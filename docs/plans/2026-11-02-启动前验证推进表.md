# CQLocalPal：启动前验证推进表

日期：2026-11-02 · 版本：v0.2 · 状态：**建议稿；任务均未因写入本表而视为已启动或完成**

> 发起人本轮要求先开放讨论，暂不设收入目标。本表的目的，是把讨论变成能逐项推进的验证工作；不预设开业日期、营收指标、融资方向或支出承诺。T0代表发起人决定开始现实验证的日期，而非自动从今天倒计时。

> **追加原则**：发起人明确两种服务均可尝试，关键看市场需求与能否跑通。不要先按发起人希望或模型偏好选择赢家。短期操作细化见[双产品14天市场验证草案](2026-11-02-双产品14天市场验证草案.md)；14天是销售准备完成后的首轮观察窗口，不能承诺届时必有足够样本。

## 1. 先列清楚要回答的问题

| 优先级 | 尚未解决的问题 | 当前竞争假设 | 最有价值的证据 |
|---|---|---|---|
| P0 | 谁在什么情境下愿意购买？ | 需要一次具体陪同体验；或需要一个远程联系人 | 最近真实经历、已采取的解决办法、完整报价后的选择 |
| P0 | 我们凭什么被选？ | 体验设计、实际陪同、个性匹配、确认与恢复能力 | 与免费工具、酒店、普通导游、¥200/trip concierge的比较 |
| P0 | 能否以合适结构稳定交付？ | 合作经营主体＋预约制供给可行 | 书面报价、职责、人员、保险、收款退款与演练 |
| P1 | 能否反复找到适配客人？ | 小住宿转介；或内容/社区入口 | 每个渠道的合格线索、成交、耗时和实际成本 |
| P1 | 实际购买动机是什么？ | 好玩、省时间、启动自由行、有人兜底 | 购买前原因、行后最有价值部分、次日使用记录 |
| P2 | 是否值得开发软件、扩大语言或地区？ | 重复工作可自动化；新增市场有匹配需求 | 当前流程耗时与新增获益，不以“有30单”自动触发 |

## 2. 推进表：先讨论和发现，再决定是否收费试做

所有负责人均为**建议分工**。AI可帮助整理、比较、准备材料，不能代替发起人开展实际访谈、签约、判断服务安全或交付。

| 阶段/建议周期 | 任务与顺序 | 建议负责人 | 可审阅产出 | 进入下一步的条件 | 未通过时怎么办 |
|---|---|---|---|---|---|
| W0／一次45—60分钟讨论 | 保留A预约首日体验与B远程支持两个候选；C住宿合作先作为渠道；写清各自假设与反例 | 发起人确定投入边界；Codex/Claude分别质疑实验 | 一页分歧表；各自报价与观察方法 | 能对两种服务提出可被市场反驳的问题；不先选赢家 | 只补会影响测试的问题；不按偏好淘汰候选 |
| W1／约半天盘点 | 盘点英语与其他语言、每周可投入时间、现有人脉/受众、合作经营主体、可服务区域、可以承担的损失 | 发起人＋潜在伙伴 | 能力/资源/缺口表，不写“都有”式概括 | 至少知道谁负责实际服务、每周可投入多少时间 | 缩小服务范围或先探索伙伴，不急于销售 |
| W1—2／建议12场20—30分钟访谈 | 访谈6名近期真实来渝/在渝的非中文熟练自由行客、3名有中国旅行经验者、3名中文可用者作对照；另访谈3家小住宿的实际决策者 | 发起人或真人访谈伙伴；AI整理 | 匿名经历卡、现有替代、实际花费与时间、反例 | 可以具体说出谁需要什么，且知道谁不需要；不按国籍推断痛点 | 样本不足写“未知”；不拿朋友赞同或网络热度补足 |
| W1—2／并行准备 | 对3家潜在经营/履约伙伴了解真实合作条件；对A拿人员、保险、协调及可用时段报价；对B测主动处理与待命成本 | 发起人＋经营伙伴/相关顾问 | 两张产品成本草表；服务职责和未决事项 | 产品有可执行的基本成本与责任安排；报价可被确认 | 删包含项、调整价格、换结构；不借名义资质销售 |
| W2／一次文案评审 | 做A/B两张产品卡：对象、具体交付、包含/不含、总价或明确待报价、时段、取消规则、主体；先做访谈刺激物 | Codex/Claude起草；发起人复核 | 两张可比较的产品卡；对¥200竞品的差异说明 | 目标游客能准确复述买到什么；测试价不会被误认已可售 | 改描述；不向未具备条件的用户收款 |
| W3—4／仅在经营准备完成后 | 给真实有日期的适配旅行组展示完整报价；每种候选累计约20次有效展示，记录拒绝原因、报价、优惠、付款及成行 | 发起人销售；合适主体收款履约 | 报价漏斗，按旅行组和产品分开 | 有若干非熟人以可持续报价真实付款；这是初步信号，不等于验证完成 | 区分没触达到、嫌贵、产品不需要、日期不合；每次只改一个主要变量 |
| W3—6／按需求推进 | 对有成交的候选做合计6—10个旅行组的小规模试做；一天先限一个现场团；远程并发另测 | 经营伙伴与具备资格人员；发起人质控 | 每单时间成本账、交付记录、异常与次日回访 | 承诺可兑现，能识别主要成本和购买原因；无未解决重大问题 | 暂停相关产品，修正范围、人员或退款安排；不靠追加免费服务掩盖失败 |
| W3—6／两项渠道小实验 | ①最多3家愿意试点的小住宿；②选一个创始人已有能力的内容/社区入口。分别限总投入约8小时，带追踪方式 | 发起人主导；AI准备素材 | 分渠道：适配线索、报价、成交、投入人时、佣金 | 至少一个入口反复带来适配询问，且交易成本可解释 | 没曝光不判需求失败；有曝光无询问检查入口，有报价无成交检查产品/价格 |
| W6／一次复盘 | 比较A/B真实付费、交付、成本和渠道；检查单位工时与供给能否持续 | 发起人裁决；Codex与Claude独立给意见 | Decision Memo v0.1 | 依据市场与交付证据确定主产品、加购、两者保留、调整或暂停 | 不强求二选一；可以认定证据不足并限定下一次补证范围 |

周期是排程参考，取决于真实客流、人员时间与合作准备。不能因为到了W6就认定市场通过或失败。

## 3. 访谈与比较方法

先问经历，再展示方案，避免把我们的答案灌给受访者：

1. 最近一次在重庆/中国旅行，哪件事最费时间或最想有人帮？当时具体做了什么？
2. 你用了什么工具、找了谁、付了多少钱？最后有没有解决？
3. 哪些部分你更喜欢自己做？哪些不愿交给陌生服务商？
4. 展示带边界的产品卡后：你会选这个、另一个替代、还是都不选？为什么？
5. 有真实旅行日期且产品已具备经营条件时，再问是否接受正式报价。口头喜欢、留联系方式、可退意向金、实际付款、成行分别记录。

先记录首次来中国与首次来重庆两个变量；另外记录中文能力、英语沟通能力、同行人数、现有中国应用经验、已有联系人与购买时机。国籍不是需求的代理指标，非必要身份信息不收集。

A/B在这里是两种候选模式的比较，不声称小样本随机实验能够证明因果。渠道、日期、人数、优惠与服务范围不同，必须留记录，不直接合并成一个转化率。

## 4. 报价与试做记录表模板

一行是一组旅行者的一次报价；改变报价保留版本。一个旅行组内的三个人不能算三次独立购买。

| 匿名组ID | 渠道 | 首次中国/重庆 | 语言及工具经验 | 人数/停留 | 候选/报价版本 | 价格与优惠 | 原有替代 | 选择与原因 | 付款/成行 | 售前/现场/售后工时 | 待命分摊 | 本地通实际收入与成本 | 异常/退款/次日反馈 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 待填 | | | | | | | | | | | | | |

指标定义：

- **合格线索**：有大致旅行日期、在服务范围内、能沟通，且提出与候选服务有关的真实需求；不是所有私信。
- **有效报价展示**：适配旅行组看到了完整价格、包含项、时段、取消与经营主体，并有真实选择机会。
- **报价付款率**：付款旅行组/有效报价旅行组；折扣、熟人、非熟人及两个产品分别报告。
- **履约记录**：准时、约定交付完成、需求变更、失联/迟到、退款、投诉分别记，不混为一个“满意率”。
- **经济记录**：整个订单与本地通自身分开核算；获客/客服人时和排班容量不能遗漏；退款负债不是可花利润。
- **支持服务记录**：同时在途组数、消息发生时间、主动处理分钟、等待和交接、超范围请求、未用支持者比例。

## 5. 怎样判断继续、修改、暂停

以下是**建议的学习门槛，不是行业标准或收入目标**。发起人可在正式测试前调整，并写下理由。

| 观察结果 | 初步判断 | 下一步 |
|---|---|---|
| 每个候选约20次适配完整报价，有3个或以上非熟人愿按可持续价格付款 | 值得继续交付观察，远不足以证明市场成立 | 观察购买理由、履约成本、第二批能否复现 |
| 只在成本价或大幅折扣下成交 | 对交付学习有用，未证明正常价格需求 | 单列补贴；试正常价格；不把免费体验转化并入付费样本 |
| 完整报价后大量选择¥200远程竞品、酒店免费帮助或普通导游 | 我们的额外价值尚不清楚 | 问清具体选择依据，改服务内容或放弃溢价 |
| 没有足够适配报价机会 | 获客/样本缺口，不能判断产品失败 | 用限定时间补一个入口；不无限增加渠道 |
| 连续试做都要大量超范围服务才满意，或扣真实时间后难持续 | 服务边界或价格有问题 | 减项、分级、改预约制、提价；再验证而非放大 |
| 经营主体、人员、保险、收退款或重大交付问题无法落实 | 相应产品不应继续收费承诺 | 先修复；访谈和不收费的方案讨论可继续 |
| 游客不买，但住宿经营者愿为明确的问题处理付费 | 可能转向B2B，而不是宣布B2C成功 | 单独验证酒店预算、决策、付款与服务频率 |
| 需求成立，但只有创始人超时工作才能交付，且暂时无法替代 | 需求和可持续交付尚未同时跑通 | 调整价格、范围、排班或伙伴分工，再观察能否复现 |

小样本下请报告“2/8组”等原始计数；不把一个退款转成百分比后过度推断。长期复购不适合作为短期游客服务的当然前提；转介绍也只有在带来真实询问或订单时才记录为相应信号。

## 6. 30/60/90天的条件式安排

| 时间窗口（从T0算） | 主要目的 | 可能的下一步 | 暂不自动发生的动作 |
|---|---|---|---|
| 前30天 | 选两个假设、补用户经历与伙伴报价、明确可售边界 | 条件成熟后少量真实报价与试做 | 不因日历到期就开发或招人 |
| 31—60天 | 跟踪成交候选的实际交付与成本；比较两个入口 | 留一个主产品和一个备用；修服务卡与排班 | 不扩多城、全语言、全品类 |
| 61—90天 | 看第二批客人和第二个履约人员能否复现；做继续/改向/暂停决定 | 若需求反复且人工瓶颈明确，考虑简单自动化；若酒店付费成立，另写B2B方案 | 不把一次旅行内多天支持称订阅留存，不把订单数量作为开发开关 |

## 7. 资源与支出：先拿报价，再决定额度

现阶段不沿用“六个月8—20万元”作为预算承诺，也不假定零成本。先分四个钱袋：

| 类别 | 覆盖内容 | 作出支出决定前需要什么 |
|---|---|---|
| 发现与准备 | 交通、访谈可能的补贴、踩线、少量页面/物料 | 发起人可投入的人时、现金上限；优先复用工具 |
| 经营准备 | 对具体产品所需的合同、人员、保险、收单和专业确认 | 产品范围、合适主体和实际报价 |
| 单笔交付 | 履约人员、协调、渠道、收款、退款/异常 | 按单成本表、现金流、取消与责任安排 |
| 不确定性储备 | 未履约应退金额、意外协调、供应商变化 | 与可支配现金分开，不能拿新客预付款填旧单缺口 |

每周只复盘：新证据、最大分歧、已投入人时/现金、下周唯一最重要实验。若新增任务，说明它会替换哪个旧任务，防止研究与渠道清单持续膨胀。
