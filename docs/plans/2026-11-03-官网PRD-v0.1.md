## 一、产品定位与目标

**一句话**：官网是外国游客从"认知→认同→认购"的完整转化机器，也是"外国人自己做的本地服务商"这一信任定位的第一证据。

**北极星指标**：询单转化率（访问→WhatsApp/预订发起）≥ 3%；次指标：评价阅读率、攻略页停留时长。

**设计哲学（创始人拍板）**：
1. **审美即战略**——创始人判断：竞品（Jay/Anjia）非技术出身，网站多为 AI 或普通外包所做，审美平庸。我们要用"技术品味"形成第一眼的信任差。宁可晚上线一周，不可丑着上线。
2. **先参考顶级，再动手**——开发前完成一轮全球标杆网站设计亮点清单（见 17 号文档），视觉对标欧美高端旅行品牌的克制感，不堆砌动效。
3. **技术路线暂缓定论**——创始人提供的公众号文章所引 Nolan Lawson《The AI cost of JavaScript frameworks》（nolanlawson.com，2026-10-28，含 HN 讨论）的核心论点：AI 生成站点中，JS 框架的每一层抽象都在持续产生成本（AI 生成 token 成本 + 访客运行成本）。仓库 docs/research/18 附录已据此完成六条结论梳理，候选方案待我方小规模复现实验后再定。本 PRD 不锁定实现栈，只锁体验与功能；性能预算（第五章）与"静态优先、轻量统计"（第六章）即该理念的直接落点。

## 三、核心页面需求

### 3.1 首页

- **首屏**：一句话定位 + 实拍短视频背景（克制处理，不自动大声播放）+ 双 CTA（"See First-Night Tour ¥399"主按钮 / "Chat on WhatsApp"次按钮）+ 信任条（Google 评分、已服务人数、随时退承诺）。
- **信任证据区**：3 条真实评价轮播（带客人姓名国家+已验证标识，含 1 条 4 星中评并附我们的回应——全公开策略的视觉化）。
- **产品三卡**：Concierge ¥199 / 首晚拼团 ¥399 / 私享定制，价格直接上卡，零询价。
- **"为什么是我们"区**：六个空位各一句话（场景/信任/响应/人格/审美/结构），配真实团队照片。
- **攻略导流区**："Planning your trip?" 三篇最热攻略。
- **零购物承诺横幅**："No shopping stops. Ever. Violated = full refund." 法律级措辞写进条款。

### 3.2 产品详情页（以英雄款为例，其他复用模板）

必须包含：时长与时间表（逐小时）→ 集合点照片级指引 → 包含/不包含清单 → 体力与饮食要求 → 退改政策（随时退+30 分钟不满意全退的醒目标注）→ 3 条该产品真实评价 → FAQ（本产品专属 5 问）→ 三币种价格切换（CNY/USD/EUR）→ CTA（订金 ¥100 或全额）。

### 3.3 攻略中心

- 模板统一：step-by-step + 实拍图 + "外国人踩过的坑"侧栏；每篇底部软 CTA（"不想折腾？我们首晚全包 ¥399"）。
- SEO 要求：结构化数据（FAQPage/HowTo）、hreflang 预留（en 先行）、URL 语义化。

### 3.4 评价页

- 全量展示，筛选器（产品/星级/日期），中评必须可见且每条中评下方有我们的公开回应。禁止任何形式的评价筛选隐藏（这是承诺，也是壁垒）。

### 3.5 预订流程

四步：选产品/日期 → 填信息（护照名+WhatsApp+航班号）→ 支付（¥100 订金，Stripe 外卡+支付宝备援）→ 确认单（含照片级落地指引+助理 WhatsApp 直连）。目标：4 分钟内完成，移动端优先。

## 四、信任组件清单（本站的"心脏"）

1. 已验证订单评价标识；2. 团队真人照片与实名；3. 外国创始人身份故事（About 页视频 60 秒）；4. 价格三币种公开；5. 零购物承诺（合同条款级）；6. 随时退+30 分钟不满意全退；7. 助理 WhatsApp 响应时间承诺（30 分钟内，08:00–24:00）；8. 实体卡照片（LocalPal Card）；9. 保险凭证展示位。

## 五、性能与体验预算

- Lighthouse 移动版 ≥ 90（性能/无障碍/最佳实践/SEO 四项）；
- 首屏 LCP ≤ 2.5s（4G 环境，重庆机房或海外 CDN——目标客群在海外，必须海外节点）；
- 图片 WebP/AVIF + 懒加载；视频仅首屏一条，其余占位图点击加载；
- 全站英文原生文案（非翻译腔），口吻=专业+有性格的朋友，禁止客服腔模板句。

## 六、非功能性需求

- **多币种**：标价 CNY，USD/EUR 参考切换（汇率月更）。
- **支付**：轻订金模式（借鉴 Anjia 验证过的闭环："A light deposit holds your dates, you settle the balance in person in China"）——Stripe（外卡）或 PayPal 收 ¥100/USD 15 订金锁档，尾款中国境内当面结（现金/刷卡），双轨并行降低跨境收款摩擦。
- **分析**：隐私友好统计（Umami 自托管或 Plausible，不装 Google 全家桶以保持轻量）。
- **合规**：Cookie 提示、隐私政策、退款政策独立页面；评价激励披露声明。
- **可维护**：内容（攻略/评价/产品）非技术人员（创始人）可自助更新——Markdown/MDX 文件驱动 + Git 管理，AI 辅助编辑。
- **部署**：静态站点 + 海外 CDN（客户全在海外，Cloudflare Pages 全球节点免备案，重庆团队访问也顺畅）；域名建议今天注册，.com 优先。

## 六之附、技术路线（2026-11-03 定稿，替原先"暂缓定论"）

> 创始人时间有限，基于 Lawson《The AI cost of JavaScript frameworks》的核心论点（JS 框架每多一层抽象，AI 生成与运行的长期成本就高一分）+ 我们的功能需求 + AI 开发可维护性，定栈如下。**如后续小规模实验推翻此结论，可回退重选，但 v1 按此执行，不再空转论证。**

| 层 | 选型 | 理由 |
|---|---|---|
| 静态站点框架 | **Astro**（SSG） | 默认零 JS、按需岛屿（islands）——与 Lawson 结论直接对齐；内容站+少量交互的最优解；Lighthouse 天然高分；MDX 内容生态成熟；内置 i18n 路由 |
| 样式 | **Tailwind CSS** | AI 生成代码友好、设计系统可约束（自定义 token 锁品牌审美）、产物小 |
| 内容 | Markdown/MDX 文件进 Git | 创始人用 AI 自助改文案；攻略批量生产；git 即版本管理与备份 |
| 预订流 | Stripe **Payment Links / hosted Checkout** + WhatsApp deep link | 不自建购物车与支付页——托管收银台 PCI 合规零负担、JS 最少；预订确认单由 AI 模板自动生成 PDF（学 Klook 即时电子凭证） |
| 无服务器函数 | **Cloudflare Pages Functions**（仅必要处：订金 webhook 记单、评价提交表单） | 静态为主、函数为辅，成本近零、全球低延迟 |
| 分析与监控 | Umami（自托管）+ Cloudflare Web Analytics | 轻量、隐私友好、无 Cookie 弹窗负担 |
| 媒体 | Cloudflare Images / R2 + WebP/AVIF | 海外访问快、成本低；短视频首屏单条、其余懒加载 |
| i18n 架构 | Astro i18n（`/[lang]/` 路由 + 文案 JSON 外置 + hreflang） | 第一天四语种就绪，内容按门槛逐个解锁（见下） |

**反选型（明确不用）**：不用 Next.js/Nuxt 全栈 SSR（JS 与 AI 成本最高、对我们纯营销+轻预订场景过度工程）；不用 WordPress/建站 SaaS（审美天花板低、与我们"技术品味"战略相悖）；不自研任何账户/支付后端。

## 六之附二、多语言蓝图（替原先"不做多语言"决策）

**四语种架构就绪，英文先行**：依据 docs/research/24 号文档的客源实证（重庆边检前五：马来西亚、新加坡、泰国、越南、韩国；携程口径渝客源前三：美国、马来西亚、新加坡），四语种为：

1. **English**（v1 唯一上线，覆盖美英澳新及全球通用语场景）
2. **Bahasa Melayu/Indonesia**（覆盖重庆第一客源板块马来西亚 + 高增长印尼，一套本地化两国）
3. **한국어 韩语**（全国第一客源国，对渝航班密）
4. **日本語 日语**（全国 top5，高客单 FIT 客群，与"安心退款"军规天然契合）

**解锁门槛（每个语种依次满足才上线）**：① 该语种客源咨询占比在 WhatsApp 后台达到 ≥15%；② 顾问级翻译校对完成产品页+退改条款（法律文本必须人工校对）；③ 客服能用该语种接待（招聘或 AI 辅助+人工兜底）。第二阶段候选：西班牙语（Civitatis 已验证）、俄语（+205% 增速）、泰语。

## 八、明确不做的（v1 范围外）

不做非英语语种内容（仅上线英文，架构四语种就绪）；不做用户账户系统（预订用邮件+WhatsApp 确认）；不做论坛/UGC 上传；不做 App；不做即时聊天机器人（真人 WhatsApp 是我们的卖点）；不做自研支付/购物车后端（用 Stripe 托管收银台）。

**关于"英文先行"的执行口径**：工程上多语言成本极低（见六之附二），约束在运营端——① 每语种 = 产品文案、攻略、退改条款、客服、SOP 的全量翻译与持续校对，退改条款误译是法律风险，客服接不住母语咨询是体验事故；② SEO 上半吊子多语言是负资产；③ 因此按"客源数据 → 顾问校对 → 客服能力"三门槛逐个解锁语种。
