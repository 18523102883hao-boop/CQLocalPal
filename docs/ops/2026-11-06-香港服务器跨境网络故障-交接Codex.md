- ⚠️ 购买时页面提示：锐驰型"公网峰值带宽通过资源池优化调度**尽可能**保障使用体验"。

## 二、故障现象

**国内 → 服务器：仅 TCP 可建立，除 8888 外所有端口无数据回传。**

| 端口 | 服务 | 国内访问结果 |
|---|---|---|
| 22 | sshd（后改 52222） | TCP 通，无 SSH 横幅 / banner 交换超时 |
| 80 | （无监听） | 快速失败 |
| 443 | （无监听） | 无证书 |
| 8888 | 宝塔 nginx | ✅ **正常返回 404（数据双向通畅，1.2s）** |
| 52222 | sshd（手工迁移） | TCP 通，banner 超时 |
| 55555 | python3 -m http.server（测试） | TCP 通，HTTP 请求超时 |

**对照事实（关键证据）：**
1. **两个独立国内网络**（重庆本地 + Kimi 云端）结果完全一致：只有 8888 回传数据。
2. **境外访问正常**：sshd 日志显示全球扫描器（如 `88.147.30.59` 俄罗斯）完成完整握手+认证尝试；实例出站正常（宝塔装好了）。
3. **sshd 完全健康**：服务器本机 `cat /dev/tcp/127.0.0.1/22` 秒回 `SSH-2.0-OpenSSH_9.3` 横幅。
4. **诡异线索**：Kimi 从国内连接 22 端口时，sshd 日志显示来源为 **`127.0.0.1`**（`Connection closed by 127.0.0.1 port 37822 [preauth]`）——疑似国内侧入口存在透明代理/NAT 劫持，且该代理对外不工作。

## 三、已尝试的排查与结论

1. ❌ 等首次初始化完成（25 分钟）—— 无效
2. ❌ 控制台重启实例 —— 无效
3. ❌ `systemctl restart sshd` —— sshd 本就 active，无效
4. ❌ SSH 改端口 52222（绕疑似 22 端口劫持）—— 仍 banner 超时
5. ❌ 高位端口 55555 起 HTTP 测试 —— 仍无数据回传
6. ✅ 已确认：非实例防火墙（iptables ACCEPT）、非 sshd、非单点本地网络

**Kimi 的假设**：锐驰型"资源池优化调度"的国内侧共享入口网关只正确转发已登记端口（8888 为宝塔预登记），其余端口数据被黑洞；境外入口无此问题。→ 属产品级缺陷，非配置可修复。

## 五、给 Codex 的尝试方向（按优先级）

1. **IPv6 验证**：实例已开启 IPv6。取控制台 IPv6 地址，从国内 `ssh -6 root@[v6]` —— 跨境 IPv6 路由常与 v4 完全不同，可能完全绕开故障入口。
2. **8888 通道利用**：8888 数据双向通畅且可控（宝塔 nginx）。可加 nginx location 反代到本地端口，理论上能搭出一条 HTTP 隧道（如 `proxy_pass http://127.0.0.1:55555`），先验证任意高位端口经 nginx 反代后国内可否回传数据，再决定能否作为部署/管理通道。
3. **无 SSH 部署路线（绕开问题）**：GitHub Actions 将构建产物 `dist/` 推送到 `dist` 分支 → 服务器出站 `curl -L https://codeload.github.com/18523102883hao-boop/CQLocalPal/tar.gz/refs/heads/dist` 拉取解压。服务器出站正常，此路线不依赖入站 SSH。适合把"网站上线"和"SSH 修复"解耦。
4. **工单/退换**：若以上均不可行，属锐驰型产品缺陷。轻量服务器 5 天无理由退款（当前第 1 天），换购**通用型** 55 元/月同规格（无资源池免责声明）。发起人可自助操作，或提交腾讯云工单要求修复入口。
5. 排查时注意：每次从国内侧测试后，查 `journalctl -u sshd -n 20` 与 `ss -tlnp`，确认连接是否到达 sshd、来源 IP 形态。
